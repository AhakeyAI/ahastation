# 终端工作区重构

后续执行入口：[终端重构规划及交付记录](2026-10-23-terminal-daemon-roadmap.md)。D0 功能离线收口与 D1 daemon 可行性及复核修复已完成；下一交付是 V1 参考图视觉实现，安排在 D2 前。下文为首轮起点及历史记录，不代表当前视觉已达到 Orca。

范围：本地 CLI 加号菜单、标签、原生终端渲染、进程生命周期。用户确认采用 Orca 的方式，并要求重构彻底、避免过度设计。多 Agent 调度沿用现有实现。

## 对照与决策

参考本地 Orca 的 `components/Terminal.tsx`、`use-terminal-controller.ts`、`lib/pane-manager/pane-dom-creation.ts`、`pane-terminal-options.ts` 和 `use-terminal-parking-pass.ts`。

- **ADR：会话不属于 React 组件。** 当前切换标签销毁 xterm 后重放 200 KiB 尾部，无法保留完整的终端状态。改为会话管理器持有 xterm、DOM、输入输出订阅；页面只挂载/移走 DOM。只有关闭标签才释放会话。
- **ADR：启动配置、会话与 IPC 分工。** 本地启动配置统一检测 CLI 和 shell；主进程服务管理会话、退出、输出序号与关闭；IPC 仅校验并转发。复用现有 PtyHost 和 Windows 启动修复。
- **ADR：终端负责字形，CLI 负责内容。** 保留原始 ANSI 和用户主题变量。采用适合 Windows 的等宽字体与 Unicode 字宽支持，提供字号调整；不解析输出重画聊天内容，不注入主题或任务。

2026-10-23 视觉澄清：上述“不注入主题”指不改写 CLI 全局主题配置；允许并需要配置宿主终端的浅色主题、字体及颜色查询，以达到用户参考图的观感。保留 CLI 原生布局和交互不等于保留 xterm 默认黑底。具体实现和真实截图验收以新规划 V1 为准。
- **ADR：界面薄化。** 复用标签数据仓库，抽出可搜索的启动菜单，加入 shell 选择、会话状态、键盘切换和关闭；工作区缩减留白，终端铺满内容区。

本轮会话保留覆盖切换标签、返回首页再进入；应用主进程退出仍关闭其终端。Orca 的独立 daemon、跨应用重启恢复、SSH/WSL/移动端属于不同生命周期，本轮不将现有内存会话冒充持久会话。原 supervisor 设计继续单独保留。
