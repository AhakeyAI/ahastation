# S5 备份生命周期与接线验收（#112，部分交付）

## 用户流程与保留策略

启动台/任务看板的“本机会话扫描”面板新增“本机会话备份”。主动刷新后只列本机准备
记录的随机 ID、Agent、时间和文件占用；不读取源 CLI 历史，不返回备份正文、原生 ID、
路径、标题或授权记录。扫描未启用或已撤权时仍可管理已保存的备份。

保存成功后默认无限期保留，用户明确确认才删除。当前 profile 最多 20 份准备记录、
总计 512 MiB（备份、独立工作副本和审计的逻辑文件字节数，不是文件系统已分配块数）。
新建前为两份源历史和最多 8 KiB 审计预留容量；不完整记录也占数量和容量。
达到上限拒绝新增并返回 `storage-full`，不按时间、最近使用或“收编成功”自动删除旧备份。
本次策略是保守默认值，未来产品更改必须显式调整并补边界验证。

删除先核对当前列表版本，再打开默认取消的原生确认框。确认后再次核对文件和目录身份、
大小及 mtime/ctime；变化时要求重新刷新。只逐个 unlink 已检查的固定结构文件，
再以非递归 rmdir 删除空目录。不跟随符号链接/目录重定向，不删除硬链接文件，
不递归删除未知目录；原始会话和项目文件从不进入删除计划。

识别的结构为 `backup.jsonl`、`manifest.json`、`native-home/sessions/rollout-<UUID>.jsonl`
或 `native-home/projects/source/<UUID>.jsonl` 及其父目录。已知结构内缺失/损坏的准备可
明确删除；出现配置、索引、新原生输出、未知文件或不可读目录时不提供该项删除版本，
同时暂停新增备份，提示检查存储。未知条目的占用可能未计入，界面显示“已知占用”。
每次最多检查 100 个顶层条目，每个准备最多 16 个节点；未知数据不无限遍历。

删除失败不回报成功。已完成的单文件删除不回滚，剩余准备按实际状态重新列出，
用户可刷新后重新确认。优先删工作副本，再备份，最后审计；不把部分失败记成整份已删除。
它不承诺对 SSD、文件系统快照或系统备份进行安全擦除。

## 代码与权限边界

- `session-copy-storage.ts`：有界清单、容量检查、版本核对、逐项删除，以及当前主进程内
  按 profile 共享的互斥门。`SessionCopyPreparer` 的完整准备过程也使用此门，多个实例
  不能绕过并发容量检查。异步失败会释放门。
- `session-copy-ipc.ts`：与扫描入口相同的主窗口/已登记项目室 sender 策略；严格空负载
  或 `{preparationId, revision}`，不接受 renderer 路径。OS 错误归一化，不泄露路径/正文。
- preload 的 `listSessionCopies()` / `discardSessionCopy(id, revision)` 仅为管理接口，
  没有创建、恢复、读取内容或执行能力。即使持有 revision，也不具备收编/执行授权。
- UI 的“准备记录”只说明审计与结构可识别，列表不重新 hash 所有历史。未来导入前
  仍必须重新验证内容哈希、归属、执行授权和目标 CLI 能力，不能把列表状态当作可执行。
- 本次没有扩大扫描权限或修改 IF-2、Hub、IF-7、CLI 配置/模型版本。

这是单主进程协调，不提供跨进程锁，也不构成对恶意同系统用户的文件系统隔离。
POSIX mode 与现有 private profile 规则不变；Windows profile ACL 仍需独立真机验收。

## 后续原生接线必须遵守

1. 原生导入、fork 输入读取与准备删除共用同一 `withSessionCopyStorage` 门。
   异步过程结束前不释放；跨进程消费须先设计租约/恢复协议，不能拿本内存门当文件锁。
2. 原生运行数据不得直接放在备份准备目录长期运行。向独立运行区导入并重新核验后，
   原生生命周期由执行端管理；备份删除不会关闭运行中的会话。
3. 源会话的执行/分享/只读授权分开。取得新原生 ID、IF-2 登记提交和实际终端就绪后，
   才可宣布“收编成功”；`prepared` 和备份列表均不是成功凭据。
4. #85/#86 的真实进程身份、输入门和 launch/bind 仍须执行端接线；当前本地
   `LocalTerminalSessions.create` 没有提供这些保证，不能直接追加 resume 参数开启收编。
5. 新的 Workflow V1（PR #172）仍在评审，且以单设备为范围。它不能自动改变 #112/#115
   的完成标准，后续按团队确认的基线接线。本次只增加可独立复用的本机备份管理。

## 验收清单

自动回归覆盖真实 Claude/Codex 主 JSONL 准备后列出/删除、源文件字节不变、相邻备份
不变、扫描撤权后管理、进程重启后的不完整准备、同 profile 并发、20 份/512 MiB
容量限制、同大小文件替换、硬链接/目录链接、未知运行文件、删除中断与错误脱敏。
IPC 覆盖非法窗口/路径/额外字段、默认取消、明确确认、确认期间文件变化及并发占用。
真实 Chromium 覆盖扫描关闭时管理、取消/失败/双击、删除后刷新、读取失败清除旧操作、
空列表及 800px 布局。

Mac/N5095 手动验收步骤（仅专用测试 profile，勿直接操作真实历史）：

1. 用合成历史调用准备模块产生两份记录；打开面板刷新，核对数量/容量和零正文/路径。
2. 停用扫描后仍可管理；取消原生删除确认，两份文件均在；重启再刷新依然列出。
3. 确认删除其中一份，核对源文件 hash 和另一份备份 hash 不变。
4. 打开确认框时修改准备文件，确认后应提示刷新且保留修改后的数据。
5. 在测试准备目录加未知文件，刷新应显示待检查并暂停新增，不递归清理它。
6. 在测试 profile 填满数量/容量，确认不淘汰旧备份；明确删除后可再次准备。
7. 核对系统确认框、Windows profile ACL、权限错误及关闭窗口行为。

自动测试不能代替上述系统弹窗、ACL 或真实原生收编验收；#112 继续保持部分交付。
