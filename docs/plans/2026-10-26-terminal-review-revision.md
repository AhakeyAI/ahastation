## 安全和生命周期回应

1. **管道权限**：当前实现仍是 bind 后由 PowerShell 收紧 DACL。收紧前 `ready=false` 的连接会被断开；完成 DACL 和发现文件写入后才接收操作。hello 还必须同时匹配实例 ID 与 256 位随机凭证。这不是创建时原子设置安全描述符的实现，也没有把单用户探针升级为跨账户渗透结论。
2. **ACL 失败**：修订后，即使以模块方式启动，ACL 或初始化持久化失败也会关闭监听端点。新增测试实际连接处于安全初始化阶段的端点，验证无数据返回、无发现文件；注入 ACL 失败后端点不可连接。另在真实 PowerShell ConstrainedLanguage 下验证 Add-Type helper 报错。受限语言机器会拒绝启动，不会回退到开放管道。
3. **正常退出和 main 崩溃**：独立 daemon 有意保留活会话。最后一个活会话结束且所有认证客户端断开后才空闲退出；未确认的树清理错误会保留。会话有明确 daemon 所有者，不能仅以 detached 标志证明无残留。
4. **升级边界**：没有新增自动升级接管、旧二进制迁出或安装器集成。D1 没有接入生产 UI；协议不兼容/认证失败不能自动重放输入或窃取旧会话。升级前应通过原实例终止会话并确认进程树退出；跨版本活会话迁移仍属于后续 D5 验收。
5. **Worker 停止**：用户停止/关闭 Worker 时立即封闭待发输入、原始键盘 IPC 和 resize，并撤销桥接凭证，等待 taskkill /T 与 PTY 退出事件后才报告 interrupted。清理失败返回错误，不生成成功停止信号；steer 保持原有回合中断。桥接服务也会在完整请求体到达后重新检查凭证，防止请求头认证后发生撤销的竞态。
6. **静默 PTY**：真实 Electron 45 回归发现，node-pty 公共 kill 会等待首个输出，导致静默进程停止后 conout worker 仍存活。修复集中在已有固定版本兼容层：确认树退出后直接释放原生资源，避开等待首个输出的关闭队列；释放时不再 fork 冗余 console-list helper，避免打包 Electron 重新启动应用。常规 kill 委派和 node_modules 均未改。回归要求测试宿主自然退出，不能以强杀测试宿主代替。
7. **测试配置隔离**：全量并行回归曾在公共临时配置的 rename 上出现 EPERM。Electron 测试 stub 现按进程创建并清理独立 userData，避免不同测试文件争用 settings.json；恢复测试也从同一 app.getPath 读取证据目录，断言内容保持原样。生产 store 的写入逻辑未改。保留首次失败、路径适配失败和修复后的完整回归日志。
