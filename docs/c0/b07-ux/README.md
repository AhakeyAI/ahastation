## 2. 信息架构

```
AhaStudio
├─ 会议（默认首页）           ← 助理对话 + 共享区
│   ├─ 左：对话流（原话、Host 回复、专家发言、系统事件）
│   ├─ 右：共享区（默认看板，可切甘特 / 文档 / 浏览器 / 成果）
│   └─ 底：语音键 + 文本输入 + 当前锁定对象指示
├─ 群聊（项目内团队消息，合并汇报）
├─ 看板（全部项目，泳道：需求 / 职能 两个维度切换）
├─ 甘特图
├─ 决定收件箱（需要我决定的事，按紧急度）
└─ 设置（服务连接、设备、额度、语音与音色、插件、自动优化）
```

会议、群聊、看板和甘特图都读取同一份领域事实（架构 11），只是不同投影。

## 3. 关键界面

### 3.1 会议（默认进入的模式；2026-10-23 用户指定布局，参考飞书会议）

```
┌──────────────────────────────────────────────────────────┐
│ [我·录音中] [助理·主持] [前端·在会] [产品·已审阅] [+ 邀请] │ ← 参会人窗格（可收起成一行头像）
├────────────────────────────────────────┬─────────────────┤
│                                        │ 会议对话 | 群聊 │
│          共享屏幕区（默认看板）          │                 │ ← 聊天窗（默认收起，
│     可全屏：隐藏参会人窗格与聊天窗       │  对话流 / 群聊   │    由底部按钮打开）
│                                        │                 │
├────────────────────────────────────────┴─────────────────┤
│ (●语音键) 状态   [💬 聊天][👥 群聊][收起参会人][⛶ 全屏][结束会议] │ ← 底部工具栏
└──────────────────────────────────────────────────────────┘
```

- **参会人窗格（顶部）**：每位参会者一个窗格，含头像、职能 + 名字、音色标识和状态标签（主持 / 在会 / 已审阅 / 录音中）；正在播报的窗格高亮并有声波动效。「已审阅」的专家窗格变淡，以区分「在会」。最后一个窗格是「+ 邀请专家」。可以**收起**为一行小头像。
- **共享屏幕区（下方，主要面积）**：默认看板。助理要切换展示时先在顶部横幅提示「助理想展示：甘特图 [切换] [保持当前]」，不直接切。聊天窗收起时，当前播报内容以横幅显示在共享区顶部。支持**全屏**（隐藏参会人窗格与聊天窗，Esc 退出）。
- **聊天窗（侧边，默认收起）**：由底部「聊天」「群聊」按钮打开，同一个窗口两个标签——**会议对话**（原话 + 锁定引用、专家发言、「未播完」标记）与**群聊**（项目团队的合并汇报）。可随时收起。
- **底部工具栏**：语音键与状态（待命 / 录音中 / 识别中 / 待发送），以及聊天、群聊、收起参会人、全屏、结束会议。录音开始时共享区显示**锁定标记**。
- 手机宽度：参会人窗格变小、聊天窗改为在共享区下方展开。
- **走查验证（2026-10-23）**：在 Electron（无窗口）中加载原型 v2，自动点击 11 步，全部通过、控制台 0 错误：默认布局、打开聊天、切到群聊、收起聊天、收起 / 展开参会人、工具栏开群聊、全屏隐藏参会人与聊天、Esc 退出全屏并恢复、短按语音键开始录音（共享区锁定、我的窗格显示「录音中」）、手机宽度无横向滚动。结果与截图在 `walkthrough/`（脚本 `walkthrough/main.cjs`，用 `node_modules/electron/dist/electron.exe main.cjs <prototype.html> <输出目录>` 复跑）。

### 3.2 看板

- 5 列固定；卡片 = 业务工作项（Issue / Story / WBS 包）。卡片上：标题、项目、职能负责人头像、细分状态徽标（阻塞、暂停、失败、状态未知、待接受、已提交、已合并、已发布）、额度使用条（标注「实际」或「估算」）。
- 维度切换：**需求**（按父子结构分组）/ **职能**（按负责人分泳道）。同一张卡片在两个维度里是同一个对象，不复制。
- 「需关注」不是列，而是顶部过滤芯片：`需要我决定 (2)`、`异常 (1)`。
- 已完成列的卡片显示终点类型：方案已验收 / 已合并 / 已发布。

### 3.3 甘特图

- 每个工作项三条线：计划（细线）、预计（虚线）、实际（实心）。预计晚于计划时只标红，不改计划线。
- 未排期的工作项放在顶部「未排期」行，不编造日期。
- Sprint 模式下显示 Sprint 边界与本轮目标。

### 3.4 决定卡片（三类分开）

| 类型 | 内容 | 操作 |
| --- | --- | --- |
| 阶段确认 | 计划版本号、目标、范围 / 非目标、验收条件、权限模式、额度 | 「确认第 N 版」/「修改」。确认绑定版本号，计划改版后旧确认失效 |
| 动作批准 | 谁要做什么（命令 / 路径 / 网络）、为什么、影响范围 | 允许一次 / 拒绝。完全访问模式下不出现（阶段确认仍要） |
| 交付接受 | 证据（测试结果、diff、独立复核结论）、遗留问题、终点要求 | 接受 / 接受并合入 / 继续修改 / 稍后。接受 ≠ 合入 |

## 4. 关键异常流程（原型中可点）

| # | 场景 | 用户看到什么 | 不能出现什么 |
| --- | --- | --- | --- |
| E1 | 远端停止未确认 | 「已发出停止，对方未确认（12 秒）」→ 超时变「状态未知」，提供「重试 / 查看执行端最近状态」 | 显示「已停止」 |
| E2 | 额度耗尽 | 卡片进入「执行中 · 暂停（额度）」；决定收件箱出现「追加额度 / 等新周期」 | 自动降级模型或静默继续 |
| E3 | 独立复核无法判断 | 「测试中 · 复核未决：无法运行 e2e 测试」，显示证据和下一步 | 显示已完成 |
| E4 | 语音项目歧义 | 助理：「你说的『筛选』是 AhaStudio 看板还是 Orca 调研？」保留原话，不派工 | 误派到另一个项目 |
| E5 | 旧批准 | 用户在离线设备上点了旧版本的确认 → 「这个计划已经更新到第 4 版，你确认的是第 3 版，未生效」 | 旧确认生效 |
| E6 | 风险直报 | 测试专家打断排队直接播报：「检测到要删除 migrations 目录，已暂停该任务」；任务卡片红色「暂停（风险）」 | 等轮到发言再说 |
| E7 | 文档接管 | 用户点「我来改」→ Agent 写入暂停，顶部显示「你正在编辑，Agent 已暂停写入」→ 交还后 Agent 先显示「检测到 3 处你的修改」 | Agent 覆盖人工编辑 |

## 5. 视觉与角色（确认单第五组）

- 稳定头像 + 轻量状态动效（说话、录音、思考、执行、待决定）；复杂 3D 和口型同步后置。
- 名字和头像可改；音色标识用一个小色块 + 音色名，便于区分。
- 手持小屏（Station）优先显示：当前任务、待决定、成果；外接大屏显示完整会议布局。原型只做大屏；小屏布局留到 B39 前补。

## 6. 待确认的交互（2026-10-23 用户已确认，**UX v1 冻结**）

用户决定：1 接受过滤芯片；2 允许纯语音确认，并同时显示确认卡片（绑定版本号与原话、可撤回）；3 顶部横幅；4 结束会议文案按原型。实现卡 A-05、A-07 可按本文直接开工。

原问题：

1. 「需关注」从列改为过滤芯片——是否接受。
2. 阶段确认是否允许纯语音确认（「确认第 3 版」），还是必须点击。规格允许自然语言确认，原型同时提供两种方式，语音确认后同样显示卡片。
3. 助理切换共享区展示时的提示样式（顶部横幅 vs 小气泡）。
4. 会议结束按钮的位置与确认文案（「结束会议：已授权的 2 项工作会继续，1 项未确认安排保留为草稿」）。

## 7. 其余首发流程（文字线框，原型 v2 再做成可点击）

### 7.1 首次引导（规格「用户主流程」第 1 步）

1. 欢迎页：一句话说明「说出目标，团队开工；需要你决定时提醒你；完成后给你看证据」。单机使用**不需要账号**。
2. 本机名称（默认取计算机名）。
3. 连接 AI 服务：列出已检测到的 Claude Code、Codex 等，显示版本和登录状态；未登录的给出登录按钮。至少连接一个才能派工，但可以跳过先看界面。
4. 允许的目录：选择一个或多个项目目录；说明「Agent 只能在这些目录和隔离工作区里写文件」。
5. 语音：选择在线语音服务（填凭据）或仅本机；在 N5095 上提示「本机语音较慢，建议联网使用在线语音」（B05 结论）。录一句话测试麦克风和回声。
6. 外部应用权限：只说明有哪些权限、什么时候会请求，**不在这里一次性申请**。
7. 自动优化：询问是否开启，默认关闭，写明「只在空闲且额度充裕时运行，不会提高额度或降低验收标准」。
8. 完成：进入与助理的双人会议，共享区显示看板（空状态写「说一个你想推进的目标，或者让我读一下这个项目」）。

### 7.2 设备配对（跨设备，首次）

1. 在设置 → 设备中点「添加设备」→ 首次时要求登录账号并**保存恢复码**（必须确认已保存才能继续）。
2. 显示配对码 + 二维码；新设备输入或扫码。
3. 新设备显示「请在旧设备上确认」，旧设备弹出确认框，显示新设备名称和指纹的后 6 位。
4. 配对成功后**不自动授权任何目录或屏幕**；新设备的允许目录要在新设备上单独设置。
5. 这一刻起开始 30 天试用计时，设置页显示精确的到期时间。

### 7.3 Sprint 生命周期

| 时刻 | 界面 |
| --- | --- |
| 开始 | 助理提议本轮目标与工作项（带额度估算），用户确认后生成 Sprint；看板顶部显示「Sprint 12 · 10/27–11/09 · 目标：……」 |
| 进行中 | 甘特图显示 Sprint 边界；每周一次进展汇总合并进会议开场，不单独推送 |
| 到期 | 自动结束，生成评审摘要（完成 / 未完成及原因）；未完成项保留「原属 Sprint 12」标记，**不自动移到下一轮** |
| 回顾 | 助理提出 1–3 条改进建议；用户可以采纳为下一轮的规则 |
| 下一轮 | 助理提议，用户确认；不自动扩大额度 |

里程碑模式：没有固定周期，只显示里程碑日期与进度。

### 7.4 通知（规格「语音与共享工具」、确认单第三组）

| 级别 | 例子 | 表现 |
| --- | --- | --- |
| 信息 | 任务开始、普通进展 | 只进群聊和看板，**不弹出** |
| 需要决定 | 阶段确认、动作批准、交付接受 | 决定收件箱角标 + 当前活跃设备上一次轻提示；会议中由助理口头提醒 |
| 无法继续 | 额度不足、服务未连接 | 同上，并在卡片上显示原因 |
| 风险 | 越权、数据风险 | **先暂停**相关任务，再在活跃设备上发声提醒；专注时段也放行 |

同一事件在一台设备上处理后，其他设备自动收起。后台默认「先提醒，用户同意后再收听」。

### 7.5 设置页信息架构

AI 服务（连接、优先级、切换阈值）· 设备（本机名称、可信设备、配对、撤销、恢复码）· 项目（允许目录、权限模式、额度周期、节奏：里程碑或 Sprint）· 额度（每个服务池的实际 / 估算用量与重置时间，单位分开显示）· 语音与角色（语音服务、每位专家的名字 / 头像 / 音色）· 插件与 Skill（来源、版本、权限、禁用 / 卸载）· 自动优化（开关、条件、用量单列）· 通知（专注时段、主动播报）· 数据（保存期限、导出、删除；删除缓存不会删除决定与验收证据）· 订阅（试用到期时间、绑定设备）
