## 对 AhaStudio 的设计推导

以下是结合产品目标提出的设计建议，不是原论文对 AhaStudio 的效果结论。

### 可扩展能力覆盖沟通到交付

建议建立少量稳定能力接口，而不是立即把每个函数都包装为插件：

1. **沟通**：ASR、TTS、轮次控制、议题识别、项目定位、grill 策略。ASR/TTS 与项目任务额度分开。
2. **知识**：原话与来源索引、项目文档检索、偏好与专业经验、冲突检测；项目访问规则先过滤，再进行相关性排序。
3. **规划**：需求到 Story/WBS、验收条目、职能任务、里程碑/Sprint；维护同一任务事实，会议/群聊/看板/甘特图消费同一状态。
4. **编排**：模型路由、服务额度适配、设备执行适配、工具与 skill。服务切换不能绕过角色最低能力要求。
5. **交付**：独立复核器、证据收集、GitHub 读写、成果展示与接收动作。
6. **优化**：失败归因、候选修改、历史回放评估、升级与回退；它消费上述各层轨迹，不直接拥有任意改写权限。

每个候选插件应声明接口版本、依赖、适用项目/平台、所需权限、配置、用量归属和日志来源。优先验证最少接口组成的真实闭环，再增加扩展点，避免首发变成插件平台建设工程。

### 分离交付闭环与改进闭环

**任务闭环**：讨论 → 确认阶段计划 → 执行 → 独立复核 → 用户接受/返工。

**改进闭环**：已结算轨迹与反馈 → 归因假设 → 插件/提示/技能候选版本 → 隔离回放及未参与优化的案例验证 → 决定是否启用 → 监测与回退。

两者分别记录预算和版本。任务重试不自动算作持久学习；存了一条经验也不等于已经证明改进。历史案例需要包含失败、边界与不适用情形，不能只保留成功样例。

### 稳定约束与版本管理

建议将权限判定、项目隔离、额度记账、授权版本、正式验收标准、证据来源与用户停止控制列为受保护契约。它们的实现可以模块化或通过受审查版本升级，但普通自优化候选不得在同一次实验里削弱这些契约、改写用户授权或把失败改判为成功。

一次 Run 记录所用策略、插件和验收版本。普通升级在新任务或明确阶段边界启用；在途任务继续固定版本，紧急停用能力可立即停止受影响执行。补偿外部操作、回滚本地文件和撤销插件注册是不同机制，不能混为“可回退”。

独立复核器本身也可被改进，但它的候选版本必须由另一套受保护的标准评估，不能由同一个候选同时降低通过门槛并宣布自己进步。

### 用什么证明值得保留

建议先采集四类实际指标：目标复述/任务创建被用户纠正的比例；阻塞澄清与错误打断；被接受交付的返工率；达到同等质量所耗的任务额度。会议次数、代码行数和 Agent 数量不作为主要优化目标。

同一案例的原版/候选比较只是起点，还需跨项目保留测试，检查权限、停止、预算、独立复核等不变量。模拟回放无法证明真实网页、操作系统或跨设备副作用正确，必要动作仍需受控集成验证。

## 复用决策仍需验证

[DeepSeek 仓库](https://github.com/deepseek-ai/deepseek-harness)标明 MIT，并提示开发预览期间存在破坏兼容性的变更；第三方依赖许可另列，不能只看根许可证。[官方安全说明](https://github.com/deepseek-ai/deepseek-harness/blob/master/SAFETY.md)明确尚未通过安全审计，不应当作已安全或生产就绪的软件；沙箱与批准不能保证隔离。

因此先将 Cordis/DSH 列为运行时与插件机制候选，与此前 Paseo 等候选按相同闭环做兼容、权限、持久化、停止、用量、Windows/macOS 验证；本次没有克隆安装、运行模型、修改 AhaStudio 代码或选定取代现有基线。

后续产品确认：首发允许自动生成和评测优化候选，启用新版本先经用户确认。默认无 Agent 执行、项目仅等人工确认或验收时，可在预留正常项目后续所需额度后使用闲置额度，项目恢复即让位。用户可设更严格条件，例如全部任务完成，或仅在额度周期即将重置且剩余充裕时运行；仍不能抢占正常执行额度。阈值、条件组合、服务周期、预留及在途调用处理待细化，以产品决策文档 D62、Q34 为准。

补充确认：优化任务启动及继续前也要评估自身消耗，结合在途用量和正常项目预留检查剩余额度；触及影响项目额度的阈值时保存已有候选与评测进度，暂停后续优化。保存不代表候选已通过或启用。优化成果默认私有，不自动上传官方或社区，用户主动分享前预览并确认内容（D63）。

开关与版本确认：首次安装启动引导询问是否开启自动优化，默认关闭；用户明确开启后才适用上述自动生成与评测机制，开启不等于授权自动启用候选新版本。用户确认启用后，新任务使用新版本，已开始任务保持原版本；已有任务仅在明确的阶段边界经检查后切换，避免执行中途规则变化。具体切换检查项与回退机制仍需验证。
