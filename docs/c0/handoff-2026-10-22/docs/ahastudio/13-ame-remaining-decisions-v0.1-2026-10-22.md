## 一 发布边界与时间

**已确认 A：** 软件与硬件分别发布。软件先验证跨设备闭环，完整功能验收后正式发布；整机通过硬件测试后独立交付，不缩减完整软件首发范围。

**已确认双向：** Windows 发起到 macOS 执行、macOS 发起到 Windows 执行两向均通过；任务按目标平台能力选择，不要求跨平台工具完全等价。

**剩余要决定：** 具体公开版本边界、可用人员、目标窗口和不可变截止条件。

**执行边界：** 软件公开可用仍须跨设备 B 和规定外测；完整正式版另须全部首发功能验收。硬件供电、蜂窝、音频、热管理独立验证，软件通过不等于整机通过。

**日期处理：** 在 C0 和实际人员确定后冻结具体日期，不重复讨论已定发布关系及双向派工。下一组进入真实 Issue 与体验者安排。

## 二 首个验收任务与体验者

**已定：** 自举 AhaStudio，先 A 后 B；至少三位未参与开发者各完成真实任务。

**已确认：** 首项任务为“看板记住最近项目筛选，刷新或重启后恢复”。用户之后创建 Issue，当前链接待补；不由本轮代为创建。

**已确认招募：** 首轮由用户或团队定向邀请三位非开发参与者，暂不公开招募；尽量覆盖固定 Agent 主机、随身项目、不熟悉代码的创造者。名单可在可安装版本后确定，允许引导但开发者不代操作。

**后续准备项：** 用户补 Issue 链接，技术团队补正反验收样例，落实设备和连接服务；可安装版本后确定体验者名单，不将这些输入误作还需重议的产品原则。

**2026-10-22 只读核查：** 主程序仓库为 `ShawnyinsGit/ahastation-internal`，`gh issue list --state open` 与 `--state all` 均返回空列表，未找到可沿用的 Issue；未创建或发布 Issue。现有 `src/components/TasksView.tsx` 中 `projectFilter` 以 `useState(ALL)` 初始化，筛选已存在而选择值未持久化。

**已确认需求边界：** 看板记住用户最近选择的项目筛选，刷新、离开再返回及重启后恢复。首次没有历史设置时仍默认全部；旧项目不可用时回到全部并说明，不影响任务记录和后台执行；保存选择以本机用户设置为限，不新增跨设备偏好同步。实现前回查周边导航行为并写明确验收，不把更大看板改造塞入这项需求。

**验收用法建议：** 将上述有限需求整理为真实 Issue 后，A 读取并语音澄清、形成带来源和条件的 TODO，B 再实现、独立验证、接受；双向跨端派工分别安排真实实现或验证子任务，保留各端证据。选定需求不等于已授权发布 Issue，仓库写入另按用户指令执行。

三类场景用于招募覆盖，不推定三人即市场验证；首轮邀请安排已确认，无需重复决定公开或定向招募。

**结束条件：** 确定 Issue 链接、正反验收例子、两设备、连接服务及三位体验者或明确招募责任人。技术人员补能力证据，不让用户回答底座能否支持。

## 三 关键默认设置

**已定：** 周项目额度可改月日，经理分配，多服务阈值接力，耗尽先问追加再问周期恢复；会议无费用上限、ASR/TTS 独立；自动优化默认关闭且正常工作优先。

**建议成套默认值，待用样机与用量数据校准：**

| 设置 | 讨论提案 | 技术团队先提供什么 |
| --- | --- | --- |
| 项目额度 | 不擅自填写统一金额；助理结合已连接服务和用户意愿建议，由用户确认分配；恢复周期尽量对齐实际服务 | 每服务单位、刷新时间和估算误差，不能凭空推算订阅余量 |
| 辅助时间 | 作为停滞提醒及可选辅助上限；不把旧 30 分钟继续当主要额度 | 不同任务耗时和无进展判定，给出是否强停的实际影响 |
| 优化余量 | 只有可保守预留正常项目和下一优化切片消耗时启动；未知余量时先停，允许用户手动预算 | 估算与在途消耗、周期和可取消能力；再建议预留比例，不先捏造百分比 |
| 通知 | 已确认普通进展不逐条弹出，能内部解决先内部处理，需用户决定、额度不足或无法继续才提醒；风险先停再通知；先提醒后收听，可设专注时段与主动播报 | 同一事件跨端去重、重要提醒及静音的原型 |
| Sprint | 已确认默认两周，可设置或对话修改，里程碑不强制周期；进展汇总与会议合并形式待原型确认 | 一轮完整生命周期的可点原型，区分 Scrum 概念和简化交互 |
| 会议恢复 | 保留项目和阅读位置；再次进入先短提示未决事项，不自动复述全部历史 | 开始、恢复、结束、归档的连续原型 |

这些默认值可以一次集中确认；按键阈值、通知秒数等由测试定，不逐个让用户猜数。

## 四 数据保存与设备恢复

**要决定：** 文字记录、日志、缓存与官方密文的保存期限，用户删除与备份范围，以及失去全部可信设备时的恢复路径。

**已确认保存原则：** 正式资料存 Git，本机文字、决定与验收证据保留到主动删除；原音不默认长期保存；缓存和普通运行日志可配置清理，不连带删除决定与验收证据。官方中转密文另定期限，不承诺永久存储。

**已确认恢复原则：** 首次跨设备引导保存恢复凭据；有其他可信设备时授权新设备并撤销丢失设备。全部丢失时用恢复凭据恢复仍有备份的加密记录；两者皆无则允许重建、从 GitHub 拉项目，不承诺找回旧加密聊天。具体密钥协议和备份存在性检查由技术方案验证。

**结束条件：** 确认各类保存原则、用户删除及备份的语义、恢复流程，具体安全实现由技术团队提供方案。

## 五 首发视觉与角色表现

**已定：** 职能＋名字、每专家独立音色、助理主要讲话，不每轮调用全部专家。

**已确认表现范围：** 首发稳定头像与轻量状态动效，突出说话、录音、思考、执行和待决定状态；支持修改名字和头像，每位专家独立音色。手持与外屏优先呈现任务、材料和成果，复杂 3D 及口型同步后置。

**结束条件：** 通过一套手持＋外屏的连续设计原型，明确头像、动效及自定义范围。若用户希望复杂虚拟形象，则作为明确首发增量估算，不由开发自行省略。

## 六 订阅与商业细则

**已定：** 本地核心免费开源；官方远程先行，两设备试用从首次成功双端远程连接起固定 30 天，显示准确到期时刻；可换绑，换绑重装重连不重置。订阅后不限绑定数，自托管后补；到期保留本地及规定收尾。

**已确认套餐结构：** 首发一个官方远程协同订阅档，订阅不限绑定；本地核心免费开源、模型服务用户自备。具体价格与服务并发待托管成本及内测数据后另提方案确认，不先编造数字。

**后续工作：** 测算金额及并发，设计换绑执行、合理使用边界、续订和到期提醒；试用算法和套餐结构不重问。

**执行流程建议，待原型：** 人工解绑旧设备再换绑，保留正在执行任务的状态说明；对丢失离线设备另给撤销路径。不限绑定不表述为无限并发，换绑界面不能将请求撤销当远端进程已停止。

**结束条件：** 定价与服务条款形成可审阅方案，试用和到期流程在两设备真实跑通；不需要等价格最终确定才验证官方连接链路。
