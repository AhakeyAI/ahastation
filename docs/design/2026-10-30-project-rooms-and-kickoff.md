# 项目室、新建项目与开场流程（设计稿）

2026-10-30 · Shawn 提出，Mac Claude 整理。对标 Orca 的项目创建代码（stablyai/orca，MIT）。

本文定义启动台「项目室」、新建项目室对话框，以及新项目进入会议后的开场流程：专家、子 Agent、工作区纪要、写入看板。

## 涉及的 AME 规则

| 规则 | 内容 | 本设计 |
| --- | --- | --- |
| AME-D11 | 助理始终担任会议 Host | 助理 = 协调者（Coordinator） |
| AME-D14 | 专家按「职能＋名字」展示，是职能负责人，可为项目派执行子 Agent，结果同步回负责人 | 专家拥有自己的子 Agent Worker |
| AME-D15 | 默认双人会议，其他 Agent 按需加入 | 用户选「脑暴 / 开发」后才拉专家 |
| AME-D17 | 同一项目只有一份正式计划 | 子 Agent 的任务挂在助理的计划下，专家只能给自己名下的任务追加消息 |
| AME-D23 | 每种模式都保留阶段计划确认 | 开场卡片列出要做的事，用户点确认即为该阶段的计划确认 |
| AME-D32、D33、Q20 | 首发 CLI 只读，不支持用户直接接管 | **本设计提供「接管」，会改变这三条**（见末尾待确认） |
| AME-D08、Q12 | 读取 Issue；回写和新建需用户明确要求 | 写入看板时单独询问「是否同时创建到 GitHub」 |
| AME-D134（接入已有项目） | 默认先只读调查 | 已有项目的空判断只读 |

## 一、启动台：项目室

**归组维度（方案 A，已选）**：一个项目室 = 一个本地 git 仓库。

- 用 `git rev-parse --git-common-dir` 找到主仓库；主目录、子目录、该仓库的所有工作树（Orca、Codex、AhaStudio 自建的）都算这个项目室的会话。
- 另一份克隆在别的目录 = 另一个项目室。
- 非 git 目录各自成一个项目室；家目录、Codex 网页对话目录等收进「其他会话」，排在最后。
- 卡片：项目名、所在目录、「主目录 + N 个工作树」、状态（几个进行中、几个等你输入）、最近活动；右下角每个会话一个 AI 头像，最多 4 个，第 4 个显示「+」。悬停列出各工作树的会话数。
- 点卡片：在主目录开会。有中断会议的，先恢复会议。

扫描、提醒、首次引导沿用上一版：首次启动引导扫描；之后自动扫描并提醒；默认显示最近 3 个，其余收起；扫描完成后全部展开。

## 二、新建项目室（取代「打开项目文件夹」和「打开本地 CLI 工作区」）

主按钮「新建项目室」打开对话框。对话框先选来源，再选进入方式。

```
┌ 新建项目室 ───────────────────────────────────────┐
│  从哪里开始？                                      │
│  [📁 打开本机文件夹]  选一个已有的项目目录          │
│  [⬇ 从 Git / GitHub 克隆]  粘贴地址或 owner/repo   │
│  [＋ 新建空项目]  起个名字，自动建好 git 仓库       │
│ ───────────────────────────────────────────────── │
│  进入方式：(●) 开会议  ( ) 只开 CLI 工作区          │
└───────────────────────────────────────────────────┘
```

| 来源 | 字段 | 行为（对标 Orca） |
| --- | --- | --- |
| 打开本机文件夹 | 系统选目录 | 直接用该目录 |
| 克隆 | Git 地址；`owner/repo` 自动补成 `https://github.com/owner/repo.git`；父目录，默认上次用的父目录，没有则 `~/AhaStudio` | `git clone --progress`，显示进度，可中止；目标目录已存在且非空时报错 |
| 新建空项目 | 名称（不能含 `/`、`.`、`..`）、位置、是否建 git 仓库（默认是） | 建目录；git 时 `git init` 并做一次空提交，没配作者身份时给出配置命令 |

- 进入方式默认「开会议」；选「只开 CLI 工作区」则打开原来的本地 CLI 工作区，并定位到这个目录。
- 启动台不再单独放「打开本地 CLI 工作区」按钮。

## 三、进入会议后的开场

### 参会者

- 用户能看到的只有：你、助理（Host）、专家。
- 子 Agent Worker 不出现在参会者列表，只出现在舞台区的标签和看板里。

### 空项目判断

进入会议后只读检查（AME-D134）：

- 看板里这个项目没有任务；
- 有 GitHub 远程时：没有打开的 Issue 和 PR（`gh` 只读查询，失败按「未知」处理，不算空）；
- 新建或刚克隆的仓库直接视为空。

满足时，助理先发一张开场卡片（出现在对话区，同时在舞台区居中显示）：

```
┌ 这个项目还是空的，先做什么？ ──────────────────────┐
│  (●) 讨论脑暴  理清目标、用户和方案，不改代码       │
│  ( ) 开始开发  定方案后由子 Agent 动手写代码         │
│                                                    │
│  确认后会：                                         │
│   1. 请「产品专家 小禾」（或「研发专家 小石」）入会   │
│   2. 专家拉起一个子 Agent，在共享区第三个标签工作    │
│   3. 助理在工作区实时整理结论、决策和待办            │
│  [开始]  [先不用，我自己说]                          │
└────────────────────────────────────────────────────┘
```

- 点「开始」即为本阶段计划确认（AME-D23）。
- 脑暴：子 Agent 只读，做资料和现状调研。开发：子 Agent 在工作树里写代码，仍按现有交付、复核流程。
- 专家用的 AI：默认 Worker 后端；助理用当前 Host 后端。

### 共享区（舞台）

标签顺序：任务看板 | 工作区 | 子 Agent（新，默认选中）。

**子 Agent 标签**

- 显示原生 CLI 画面（Claude Code / Codex 终端）。
- 顶部一行写「专家 小禾 正在让子 Agent 做：<当前任务>」，右侧「接管」按钮。
- 默认只读，用户不能直接输入。
- 消息流只显示两类内容：讨论内容摘录、专家给子 Agent 的派活消息。
- Claude 的「信任此文件夹」询问出现时，标签内显示「信任这个工作树并继续」按钮。这是用户明确操作，不算接管；修复 #125 的卡死。

**接管弹窗**

```
┌ 接管子 Agent ────────────────────────────────┐
│  专家已经给它安排了这些事：                   │
│   ✓ 读 README 和目录结构                       │
│   ▶ 调研同类产品的 onboarding（进行中）         │
│   · 汇总三种方案的优缺点                        │
│  接管会先打断子 Agent 当前的工作。              │
│  [打断并接管]  [继续看]                        │
└───────────────────────────────────────────────┘
```

接管后终端可输入，标签顶部变成「你在操作」加「交还给专家」。交还时专家先读你改过的内容再继续，参照 AME 里文档接管的交还规则。

**工作区标签（默认内容改为会议纪要）**

助理基于讨论实时整理，分四块：

- 核心结论（已确认的事实）
- 决策（谁定的、依据）
- 待办（要派工的工作项）
- TODO（零碎的后续事项）

每条带来源（哪一轮发言）。底部按钮「确认并写入看板」。

**写入看板**

- 弹窗列出将创建的看板卡片，可勾选。
- 下方单独一项「同时在 GitHub 创建 Issue」，默认不勾（AME-D08、Q12）。项目没有 GitHub 远程时这一项置灰。
- PR 只在开发阶段由交付流程产生，不从纪要直接创建。
- 写入后卡片进入看板的「待执行」，不自动派工；派工另行确认。

## 四、实现分期

| 期 | 内容 | 主要改动 |
| --- | --- | --- |
| P1 | 项目室按 git 仓库归组 | 主进程 `projects:resolve-repos`（只读 git，缓存）；启动台归组 |
| P2 | 新建项目室对话框 | 主进程 `projects:clone`（带进度、可中止）、`projects:create`；启动台入口整合 CLI 工作区 |
| P3a | 开场卡片和专家入会 | 空项目判断（只读 `gh`）；开场卡片；用现有 `sessions:add-host` 拉专家并设职能名字 |
| P3b | 专家名下的子 Agent | 开场计划由主进程生成、用户点「开始」即批准；任务带 `ownerHostId`；专家获得「只能给自己名下任务发消息」的工具；Worker 结果同步给专家（AME-D14） |
| P3c | 子 Agent 标签和接管 | 第三个舞台标签；只读终端；信任框按钮；接管弹窗（读取任务计划和消息）；打断后开放输入 |
| P3d | 工作区纪要和写入看板 | 助理工具 `update_meeting_notes`；纪要面板；写入看板（待执行卡片）；可选 `gh issue create` |

## 待确认

1. **接管会改变 AME-D32、D33、Q20。**这三条现在写着首发 CLI 只读、不支持接管。本设计按 2026-10-30 的要求加入「打断并接管」，需要把这三条改为「专家子 Agent 的 CLI 可在打断后接管，交还时专家先读变更」。
2. 开场卡片的「开始」作为 AME-D23 的阶段计划确认，不再额外弹计划审批。
3. 纪要的待办写入看板后，放在「待执行」，并沿用 U3b（#123）的「只建卡不派工」状态。
