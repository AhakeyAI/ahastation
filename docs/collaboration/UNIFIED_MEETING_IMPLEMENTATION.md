## 1. 修改目标

用户只使用原有的会议主窗口，以及其中的“会议／任务”两个视图：

1. 设置完成协作账号、本机接入和首次共享 Agent 授权；从原首页新建／恢复会议，新建时选项目／目录及 Host，纯文字可不选用户项目。
2. 在原参与者区域邀请本机／远端参会 Agent，或明确关联已有 Codex 原生对话。其他设备可先加入交流，需要文件操作时再在对应设备绑定项目目录。
3. 在原聊天区提出完整目标，由该会议原 Host 统筹、澄清并拆分独立完整交付。
4. 在原计划审阅界面看懂成功标准、做法、拆分理由、完整任务、依赖、执行设备和验收要求。
5. 按手动／自动分配及独立的计划批准规则，安排本机或远端执行。
6. 原会议和任务看板显示同一任务的进度、等待原因、实际执行人、成果及检查状态。

保留同一会议唯一 Host、一次计划权威、同一业务任务身份。独立 SharedMeetings 面板不再承担正常使用流程；不能同时让它和原 Orchestrator 消费同一条用户指令。

### 3.2 原参与者区域

设备断线保留卡片、任务及最后已确认状态；不因为 UI 看不见或窗口关闭而判断任务终止。原型允许切到 B 视角，查看断线后留在执行设备上的本机成果。

聊天是同一会议的群聊，消息、计划和结果按时间显示，各设备看到同一条记录。普通消息由原 Host 按原会议规则回应，不因发言就机械创建任务。没有常驻“发送给”下拉框。

Q95 已确认普通消息默认由 Host 回应，@ 指定对象由该对象回应，Host 可主动咨询其他参会 Agent；不因成员数量增加就全员自动调用。执行进度、完成结果和审批请求继续主动回报。这是回复路由和调用触发规则，不限制其他设备在 UI 中查看同一聊天记录。

Q100 已确认保留：原本机 talker 与 Worker 会话分别管理，@ 专家路由未因 Worker 忙而关闭，任务执行期间的独立专家交流按原功能保护要求保留。不要将它描述成正在执行的同一任务对话并行聊天，也不保证专家完整拥有该任务实时上下文。新跨设备成员身份和任务关联仍需整合，原生同对话串行规则不变；日常继续由 Host 统筹，无需用户逐一联系执行者。

| 执行中 | 明确哪台电脑的哪个 Agent 在做哪项任务 |
| 停止待确认 | 请求已保存，实际退出尚未确认，不提前释放占用 |
| 已停止 | 原任务、对话、文件和提交保留，只能明确继续 |
| 成果已上传 | 文件和准确提交可获取，还不能冒充检查通过 |
| Host 检查通过 | 对应报告、测试和组合证据已核验，仍待最终验收 |
| 最终验收 | 用户确认交付；GitHub 合并仍另行决定 |

### 3.5 成果与原生对话详情

成果沿用原摘要、文件、测试、差异和历史设计，加入来源设备、仓库、准确提交、分支与 PR。可以在 PR 未合并时获取独立成果副本；不能悄悄覆盖当前项目或自动合并。

原生对话详情保留原上下文和来源，展示桌面输入／输出与 Station 点名内容；桌面轮次完成或确认停止后接续。普通点名不自动变成正式业务任务。正在执行或停止待核对时，不能取消选择后让对话从会议里消失、底层却继续运行。

Q90 已确认会议主聊天只自动展示本次接续的指令、状态和结果摘要；选定历史留在对话详情。UI 可查看完整选定历史不代表所有参会模型应取得这些历史，模型输入组装只提供明确引用／任务所需摘要，并保留来源。不能只隐藏 UI 文字，却在 Host 快照或其他 Agent 请求里注入整条原生历史。

## 5. 修改后的完整运行过程

1. A、B 启动 Station，在设置登录同一协作账号，完成本机接入；检测已有 Codex 登录，明确允许本机接收。
2. A 从首页创建会议，选择已有工作项目／本机目录或纯文字，并确认 Host；原默认可沿用，已有会议直接恢复。仓库缺项可就地准备，本机项目与 Host 参考范围明确。
3. A 进入统一会议，在参与者区域邀请 B 的参会 Agent；需要本机执行时再勾选 A。A 承载会议唯一 Host，选择项目不自动选择 A 执行。
4. B 打开同账号既有会议，先查看和交流，不另建 Host；需要项目文件操作时，在 B 选择／克隆对应副本并确认本机授权，已有有效绑定复用。GitHub 和目录不是纯文字交流前置项。
5. 用户在任一端提出目标。Host 提供可读计划，说明拆分原因、各项完整交付、依赖、设备与 Agent。
6. 手动模式由用户指定设备／Agent；自动模式由 Host 明确安排。计划按所选批准规则处理，设备不可用时等待或提出明确修订，不暗换目标。
7. 统一派发保存任务，执行设备再次核验、落盘并确认接收；之后等待名额、准备独立工作区并调用本机 Agent。
8. 参与者显示正在执行的任务；原任务界面显示实际阶段。B 已接工作可在断网后继续，结果留本机、恢复后补传；未接工作等待。
9. B 提交准确成果版本、结构化报告与实际测试。Host 检查、组合验证并汇总；A 可在 PR 未合并时获取独立成果副本。
10. 用户查看并最终验收，GitHub 最终合并仍由用户决定。
11. 如会议关联 B 的既有 Codex 对话，用户可明确点名远程接续；它保留原身份与上下文，主聊天展示本次指令／状态／结果摘要，详情看原历史，其他模型仅获明确引用／必要摘要，互不重复派发。

A 离线时仅已被执行设备确认接收的工作继续；新拆分、派发、补充投递和继续请求等待 A，停止仍可处理。关闭窗口／暂离界面不等于退出执行。
