## 发现

### P2：保存协作凭证后，关闭原单机窗口也被拦截

证据：electron/main.ts 的 createWindow close 回调使用 `!isQuitting && sharedRuntime?.view().credentialReady` 即隐藏窗口并 return；station-service.ts 的 view 将 credentialReady 定义为本地 tokenEnc 是否存在。这里没有检查协作当前是否启用、是否承担接收／主持，或用户是否选择后台运行。

因此，曾经接入过设备、后来关闭协作或仅使用原单机会议的用户，也可能从原先的关闭流程变为直接隐藏。该条件还位于原 suppressNextClose／最小化确认逻辑之前。源码能确定分支会改变，不等同于所有平台都已实机复现。

建议：将后台保活限定为明确启用的协作运行状态及已确认的后台运行规则，未启用时仍走原关闭／最小化逻辑；关闭界面、停止单个任务、退出应用三种动作分别回归。保留真正接收中任务的后台能力，不能为恢复原行为而直接杀掉共享执行。此轮只记录，未修改生产代码。

### P1（已知整合缺口）：原会议与新增共享会议仍是两套入口和 Host

证据：src/App.tsx 分别在 Lobby／原会议分支挂载 SharedMeetings；CollaborationPanel.tsx 自行保存 selected、message、target 等状态，并创建独立覆盖层；electron/collaboration/coordinator.ts 使用独立共享统筹链路。原 SideDrawer／meeting-store／Orchestrator 未因此获得新共享投影。

现有原 @ 功能还在，但新共享面板没有自动继承它。仅修改 HTML 或删掉浮层按钮不会完成整合。要按 UNIFIED_MEETING_IMPLEMENTATION 的 P1–P4 接入同一会议、Host 和业务任务，避免两个处理者消费相同指令。此项直接影响“原会议中使用新能力”，并非证据表明原单机聊天已损坏。

### P1（已知分配差距）：当前自动派发会重新选设备

证据：station-service.ts 自动分配循环按 activeTasks 排序 eligible，并用首项覆盖 targetDeviceId。它可能不遵循 Host 已显示的目标。与 Q75／T33 不符，仍须后续实现。不得把它描述为已完成的“原 Host 安排”。

### 待验收：界面、快捷键和原有平台行为不能靠类型检查证明

2026-10-22 补充：原“多 Agent”开关与计划批准存在耦合，属于原行为与新规则的整合冲突。App.tsx 的 multiAgent 会经 setOrchestrationMode 设置 Orchestrator.autoOrchestration；proposePlan 在其为 true 时直接安装计划。它不是全体 Agent 自动回复的开关。已确认的新规则要求计划批准、设备分配和协作组织分别处理，因此后续不能直接把该布尔值用作隐式自动批准。此为源码核查，未在本轮运行真实会议复现，也不归类为新增候选代码导致的回归。

SettingsWindow 保留原 Backend、IDE、Memory、Voice、VoiceLock、Skill 和 Upcoming 区域；新增 CSS 大多限定 collaboration-*。SideDrawer、meeting-store、Orchestrator 等原核心文件相对当前 HEAD 没有候选修改。这能证明没有直接删除这些入口，不能证明覆盖层焦点、窗口隐藏、初始化失败、语音、屏幕或真实模型没有间接影响。

## 保护矩阵

| 原功能 | 实施允许的接点 | 必须保留／核验 |
| --- | --- | --- |
| 单机会议、任务、项目切换和恢复 | 对共享会议显式启用投影／动作适配 | 未启用协作的原状态、持久化、计划、恢复路径；旧记录仍能打开 |
| 原 Host、批准、任务调度和交付检查 | 扩展设备上下文和执行路由 | 目标处理一次、审批规则、结构化报告、检查和最终验收；不创建第二个 Host |
| 群聊、@、斜杠技能和附件 | 扩展参会对象的稳定身份及可读标签 | 原键盘操作、邮件／普通 @ 文本、歧义和离线保护；本地附件与已共享文件的原边界 |
| Codex 及其他 Agent／自定义后端 | 使用适配器与能力门控 | 原登录、模型、API 配置和凭证隔离；不因首版只扩展 Codex 就移除其他 Agent |
| 语音、ASR／TTS、声纹和中断 | 复用既有文字归一化和点名路由 | 配置入口、输入、播放、语音点名歧义处理和原中断语义 |
| 屏幕共享、快照、文件与浏览器 | 通过原组件使用 | 原授权、文件预览、截图和浏览器生命周期；新浮层不永久遮挡或抢焦点 |
| 记忆、技能、IDE、AhaBar 和观察服务 | 不做无关改造 | 原入口和开关、快捷键、配置读写不受新配置迁移影响 |
| 窗口关闭、最小化、托盘与退出 | 仅明确协作后台运行场景补充保活 | 纯本机路径不改变；正常退出核对实际执行；关闭设置不关闭主窗口 |
| 服务故障、撤销和恢复 | 新协作错误局部呈现 | 不能让 Hub 断网、凭证失效、接收组件不可用阻断原单机功能 |
| 打包与跨平台 | 新资源按平台追加 | Windows 构建可启动；原 macOS／Linux 能力不得静默删除，未跑平台列待验收 |
