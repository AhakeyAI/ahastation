# 发给新成员的分工说明

这次我们想把 AhaStation 做成两台电脑都只安装 Station，就能登录同一账号、加入同一个会议、分配和执行任务。各台电脑操作自己的本地项目副本，通过同一个 GitHub 仓库提交修改和 PR，不要求两台电脑使用相同的文件夹路径。

我们按完整功能模块分工。你负责“设备接入与管理”和“项目绑定与授权”：从设置界面、Electron 本地服务，到对应的 Hub 接口和测试，都由你完成。设备部分包括启用本机、注册和命名设备、选择 Agent、接收任务开关、并发设置及同账号设备状态；项目部分包括逻辑项目和仓库关联、本机副本及任务工作区绑定、权限配置，以及供执行模块调用的本地授权核验方法。你也会做后台和接口，不只是前端。我负责共享会议、Host 拆分任务、手动／自动分配、远端执行、结果回传、停止和断线恢复。云托管部署和数据库迁移由我统一操作，你不需要云平台管理权限或现有业务数据库密码。

正式开发前，我们先一起准备公共基础 PR。我先整理当前必要源码、可复现的代码版本、已有登录和通信调用方式、启动测试说明及测试配置；你先跑通项目，梳理自己模块需要的字段、方法和异常情况。然后我们共同确认设备信息、项目信息、本地授权核验、状态变更通知这四项契约，把数据结构、请求／响应样例、模拟实现和基础测试放进 PR。这个阶段先做到双方能按同一套接口开发、完成测试消息往返，不要求先做完设备和项目的全部功能。当前这两份说明文档只是准备材料，公共基础 PR 还需要实际整理代码并提交。

公共契约合入后就可以并行开发：你做设备和项目，我用模拟设备与绑定开发会议和任务。你的最小能力完成后，我们马上联调“B 注册设备 → B 绑定项目 → A 分配一个任务 → B 执行 → A 收到结果”，再逐步补齐自动分配、停止、恢复和 GitHub PR 交付。具体需求、现有代码入口、尚未完成事项和验收标准见配套交接文档。
