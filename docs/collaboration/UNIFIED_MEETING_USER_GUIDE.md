# 统一会议使用说明（0.19.0-collaboration.2）

这是本轮源码和 Windows 候选包的使用说明。现有微信云托管 Hub 可以继续使用同一域名、账号、数据库和服务；需先由有权限的操作者部署同版 Hub 包，才能创建统一会议。旧 Hub 没有 `unified-meeting-v1` 能力时，Station 明确提示升级，原单机功能仍可用。

1. 设置 → 协作接入。在「Station 账号与本机」正常登录原账号，确认首次本机共享授权及允许使用的 Agent；需要接任务时开启接收。已有身份和登录直接检测、复用。共享正式执行适配为 Codex；其他 Agent 显示真实安装、认证和适配状态，其原本机功能保留。
2. 回首页。在「同账号会议」恢复既有会议，或展开新建会议，先选择纯文字、用户指定仓库或本机目录及 Host。新目录／仓库在当前流程选择本机副本和独立任务工作区、确认授权。已存在项目缺本机授权时点就地绑定按钮。纯文字不需要 GitHub 或用户目录。
3. 用原「＋／Participants」邀请「设备名 · Agent」。本机明确标记，默认不选入；勾选只成为执行候选。取消勾选仍保留成员、讨论及已接任务。另一端直接进入同一个会议，不创建第二个 Host。
4. 在 Chat 提目标，默认由 Host 回应。原 @ 候选和键盘操作用于明确专家或已有原生对话；普通 @ 是独立会议讨论。新成员加入不调用模型，首次点名才取得必要背景。语音点名、附件、截图、斜杠技能继续沿用原入口。
5. Host 用原编排提出完整交付计划。在原计划审阅器编辑目标、做法、步骤、风险、任务、依赖和责任设备。手动选择目标，或让 Host 自动提出目标；「自动批准后续计划」另行显式控制，默认关闭。批准后目标暂忙时等待原设备，不自动换机器。
6. 文件工作在各执行端分别绑定并授权自己的副本。Station／Agent／GitHub 身份分开，本机路径与凭据不上传 Hub。文件、附件和截图只发布用户选定资料到所选 GitHub 资料仓库，引用准确提交和路径；不能自动上传整个项目。共享输入资料在读取设备也要有相应仓库授权。
7. 原参与者卡、会议任务表及任务看板显示同一任务。打开详情看目标、依赖、实际状态、审批、补充、活动和成果。远端活动标成同步记录，不伪装为本机终端。工具审批集中显示，按钮为「允许这一次／拒绝」；不支持的原生交互明确去执行端 Codex 桌面处理。
8. 修改正在做的工作，从指定任务卡，或在聊天的「关联任务补充」明确选择任务后发送。普通 @ 不猜最近任务，不广播所有任务。保存成功只表示保存，到轮次边界才投递。已停止任务可以编辑／忽略补充，并须明确继续；最终验收后的独立追加工作作为关联新任务。
9. 成果查看摘要、文件／图片／文档、Diff、真实命令退出码、准确提交、分支和 PR。本机须授权相同成果仓库才能读取准确版本。代码成果先经过结构化检查和组合验证，再释放依赖；自然语言“测试通过”不能替代实际证据。最终验收不自动合并 GitHub PR。
10. 已有 Codex 对话在参与者中明确选择设备、标题和原生身份。主聊天显示本次指令、状态和摘要，详情看选定历史；其他模型默认没有完整原生历史。同一对话桌面与 Station 串行协调，桌面完成或确认停止后接续。
11. 底部 Interrupt 先选停止 Host 回复、指定任务或本会议全部当前执行；全部停止再次确认。等待真实退出前名额不释放。首页／Leave 是暂离视图，保留已接任务。完全退出或协作登出按执行核对流程处理，不关闭无关 Codex 桌面。
12. 高级设置保留恢复码、撤销／重新授权、服务地址、LAN／自托管、并发、权限上限及组合验证命令。模型、语音、声纹、技能、记忆、IDE 和其他 Agent 原设置入口保留。

原 Pocket Vibe 适配器保留旧执行核对和停止。旧共享会议可在无在途工作并核验后接入原 Host，保留业务 ID 与旧线程历史；不会把旧原生线程假称转换为新线程。未完成旧记录实机迁移验收前不删除适配器。

本机只有一台电脑。本轮单机多进程／协议回环、真实模型和打包检查不能替代两台物理电脑／公网／真实 GitHub 仓库验收。逐项证据见 [本轮交付记录](UNIFIED_MEETING_DELIVERY_2026-10-22.md)。
