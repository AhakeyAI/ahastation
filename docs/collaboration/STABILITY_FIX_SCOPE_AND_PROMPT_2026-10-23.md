## 一、最终修改范围

1. **专家与 Host 执行隔离及失败恢复（F1、Q105）**：互斥与恢复对应明确对话／输入，不因同会议或同品牌误锁。专家准备失败在原点名消息显示原因；确认未启动才允许明确重试，保留设备、Agent 与会议交流背景。实际未知继续核对，仅相关对话等待。
2. **同一次消息提交与输入保护（F2、Q102–Q103）**：连点或连续 Enter 不形成两个提交；发送期间可以编辑下一条，成功不能擦除新输入。Hub 确认后可发下一条，不必等模型结束。回执未知核对／补投原提交，网络重试不再生成消息或执行。正文、@、任务关联、附件保持同一提交版本；用户明确再次发送相同正文仍可成为新消息。
3. **原计划窗口的编辑与版本保护（F3、Q104、Q106–Q107）**：只保护现有审阅字段，不新增草稿模块。相同快照及无关状态更新不擦除编辑、不新增提示／操作；实际计划变化才提示并保留修改。Host 与人工提交两路都核验各自依据的版本，不能用迟到旧结果覆盖新安排。关闭查看不等于拒绝；本机本次运行按会议保留未批准修改，明确放弃才丢弃。查看／编辑不暂停已获准工作或暗改自动批准策略，已分发字段不可变。
4. **Hub、数据、原功能及匹配交付**：必要协议与 Hub 同步修改，复用现有 MySQL 5.7、station_hub、身份与记录；无必要不新增 DDL。保护原 R1–R4、统一会议、单机及其他无关功能，修复后测试、构建、打包并给出来源一致的证据。

明确不做：会议／账号全局锁、把所有对话串成一条队列、新的任务暂停／取消体系、独立草稿中心、额外保存／发布流程、未批准修改跨电脑同步或跨应用重启恢复、自动扩大权限、重置数据库或设备。已提交消息、任务、会议与原生对话的既有持久化／恢复不受上述临时编辑范围影响。
