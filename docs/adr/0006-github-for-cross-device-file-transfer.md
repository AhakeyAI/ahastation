# 通过 GitHub 传递跨设备输入与成果文件

首版统一通过用户指定的 GitHub 仓库传递跨设备文件，不预置统一中转仓库：A 只提交选中的输入资料并推送，任务携带仓库、准确提交号和文件路径，B 拉取指定版本执行，再将成果提交到独立任务分支并返回提交号、文件清单及 PR；A 可以在 PR 合并前获取对应提交的真实成果，非仓库任务则在普通授权目录执行并借助所选资料仓库传递文件。输入资料保存在资料分支，成果 PR 默认只包含应交付的修改，需要作为项目文件保存的输入再明确纳入；首版使用普通 Git，大文件／Git LFS 支持后续增加。Hub 仅同步任务、进度、结果和文件引用，不新增附件中转服务，不自动上传整个本地项目目录，未提交或未推送文件不视为已共享；相应代价是跨设备文件依赖双方的仓库权限和 GitHub 可用性，会议内代码整合与最终合并边界见 ADR-0007。
