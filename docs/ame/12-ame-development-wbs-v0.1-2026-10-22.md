## 计划基线

（10-27 更正）主程序源基线改为 main `c8295b9`。原文所写的 `bb765223e34cd2ca7c08052cd24b34e9f7bd84ac` 是旧检出，只作历史保留。原文：主程序源基线为 AhaStation 0.18.4、`bb765223e34cd2ca7c08052cd24b34e9f7bd84ac`，2026-10-22 只读核对仍一致，保留用户锁文件和其他检出改动。实施前应在有真实源码的独立工作目录冻结 SHA、锁文件和工具版本。

旧 07/08 文档的人日与排期来自 macOS 单机及旧范围，保留为历史。新范围增加 Windows＋macOS、跨设备、官方托管、双维度看板与甘特图、Sprint、内置工具、插件和可选 RSI；不沿用旧 132 人日或 22 周作为新承诺。新预算优先级也已由阶段 30 分钟改为项目周期额度。

本版采用相对规模：S 为已有边界内的有限改动，M 为跨若干模块的行为闭环，L 为多个状态或平台协作，XL 为须先切片验证的高不确定工作包。它们不是人日，不能直接相加换发布日期。C0 验证后，由实际负责人对首批就绪包拆到可评审切片，给出人日区间与资源排程；候选不成立时重估依赖，不靠删验收缩短工期。

## 关键依赖与并行边界

主闭环之一为 B01 → B02 → B08 → B12 → B18 → B21 → B22 → B23；B21 同时依赖运行适配与 B19 预算，不能只按这条链独立开工。跨端分支 B27 → B28 → B29/B30 → B31 与主闭环汇合。B35/B36 必须在真实交付与预算可用后验证，不能先写自优化提示词就标完成。

可并行的是有稳定接口的工作：C0 的运行底座、语音和额度验证；领域契约稳定后的界面原型、持久化和设备协议。共享状态、权限、账本、数据迁移先有唯一 owner 与版本契约，再拆多 Agent。并行分工不能把同一文件目录当安全边界，也不让多个 Agent 自行修改同一正式计划。

## 每包执行和验收要求

每张实施卡记录：WBS ID、实际负责人、源与目标版本、允许修改范围、前置证据、输入输出、可检查验收、额度和权限、回退方式。包内可再拆细任务，主包按用户成果验收；默认不为每个实施细节创建 GitHub Issue。

验证最高可观察行为，补真实回归或新边界的测试，不写仅镜像实现的断言。需要 paid 模型、外部写入或样机操作的测试单独列预算和授权；本规划不自动执行。验收保存 app/OS/Harness/插件/计划/成果版本、命令结果、用量质量、日志和人工判断，用户数据共享前按所选范围处理。

工作包进入已完成必须满足其约定终点及独立复核；父级版本还需整体测试与用户接受。修改依赖、首发范围或估算时，规格、WBS 和确认单同步更新。
