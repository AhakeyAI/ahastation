# collaboration.4 升级与回退

本候选修复 Q102–Q107 / F1–F3。Station 版本为 0.19.0-collaboration.4；部署随本次交付的匹配 Hub。现有微信云托管 Hub 可以继续使用，本任务没有部署或重启生产。

## 数据与配置

- 继续使用 MySQL 5.7、原 station_hub、账号、设备、凭据、授权、任务、消息、事件和请求幂等记录。
- schema=2 **不新增 DDL**。计划内容版本 planVersion、批准决定版本 planDecisionVersion、planProtocol 和消息 submissionId 都保存在原实体 LONGTEXT 中；原请求表继续原子记录幂等结果。
- 旧实体缺少计划版本时按 0 读取，第一次实际计划修改才推进内容版本。身份和既有记录不重建。Station 原 outbox 原地恢复，同一次提交继续使用原 requestId。
- 保留 HUB_SECRET、数据库密码、服务 HTTPS 地址和非公开环境变量。Station 仍仅使用 HTTPS/WSS，不能给它数据库连接信息。
- 若原库仍是 schema=1，才执行已有 MySQL 5.7 增量升级材料，见 MYSQL57_HUB_UPGRADE.md；这不是 .4 新增迁移。schema=2 不重复跑建库、清表或初始化操作。

## 操作顺序

1. 核对 SHA256 清单，保留当前 Hub 镜像／代码、Station 安装器、非公开部署配置和 Station 当前 Windows 用户 profile 的 collaboration 记录。对 station_hub 作一致性完整备份并核对恢复可读性。备份包含敏感数据，私下保存。
2. 选择维护时段，在原设备停止接收新工作；完成或明确停止并核对当前执行。未知状态保留原设备／原对话，不重派、不删除记录，也不关闭用户 Codex 桌面工作。
3. 使用新 Hub ZIP 根目录作为 Docker 构建上下文，沿用现有配置。先部署 Hub，再更新参与设备的匹配 .4 Station。通过 /health、/ready、正常账号登录、原设备 identity、快照和 WSS 检查，不更换密钥或重新注册全部设备。
4. .4 Station 要求 Hub capabilities 包含 unified-stability-v1。旧 Hub 会明确拒绝继续新协议，原记录保留。旧 Station 可保留旧协议的恢复路径，但不能修改已启用版本保护的计划；返回 426。原 original-orchestrator 会议的计划写入也必须带明确版本，避免旧迟到输出覆盖人工安排。升级相关设备后再恢复新派发。
5. 核对原 outbox 待提交消息；响应未知时使用“核对／补投原提交”，不复制正文另发。已开始而未知的模型执行继续核对，确认未启动的专家／Host 输入才从原消息明确重试。
6. 旧 Host 恢复输出若没有保存计划依据，只保留回复并显示未应用计划的原因，不能补上当前版本强行覆盖。确需新安排时，在原会议明确要求 Host 基于当前计划提出新建议。
7. 按交付报告 S01–S18 执行现场检查，确认后恢复接收。回环、UI 夹具和独立库不代替双物理电脑／公网、实际 GitHub、用户桌面及硬件验收。

## 界面行为

正文、稳定 @、任务关联和附件属于一次固定提交。连点／Enter 防重入；等待确认期间可编辑下一条，旧成功回调不能删除新内容。Hub 确认即解锁下一条，不等待模型结束。

原计划窗口的修改仅在本机本次 Station 运行中按服务／账号／设备／会议保留。关闭查看不拒绝、不批准或暂停；“放弃本机修改”只清该份编辑。应用重启不恢复未批准编辑，已提交业务记录照常恢复。无关心跳、名称和进度不改变计划版本；内容及安排相同的 Host 再提案保留已有批准，不要求重复批准。真实新版保留当前编辑，核对后载入新版或显式应用自己的修改；提交仍检查最新已分发字段。查看／编辑不改变自动批准策略；关闭自动批准只影响后续提案。

## 回退

停止新接收并核对所有本次新增／未知执行，保全上线后的 Station 原记录、Hub 事件与数据库增量。保留故障日志和新包；在维护窗口一起切回已保留的旧 Hub 版本和相匹配 Station，沿用原数据库／密钥，不做反向 DDL。旧版本会恢复 F1–F3 的已知缺陷，不应在旧版继续这些新流程；优先前向修复。

不能直接把升级前 SQL 备份覆盖到已产生新业务的库，不能删除 .4 的新字段、幂等记录或 Guardian 日志来解锁执行。若基础设施损坏确需备份恢复，应先保全并核对升级后增量，由操作者在独立库验证后实施。原生执行始终留在原设备核对，不以回退为理由重新启动未知工作。

## 外部条件

本机没有 Docker 引擎，交付会检查 ZIP 清单、Unix 权限、固定依赖、Docker COPY 来源并隔离启动导出的生产 app；Linux 镜像构建与云托管上线仍需有引擎的环境执行。Windows 安装器签名状态见交付报告；本任务不覆盖现有安装。
